# xltwrun: clean re-runs of the 7 paused instances (rule fixed 2026-11-08, before the job runs)

MV2 of Munim, Inc. (mv2@munimtech.com). Made with AI agents working in MV2's name. CC BY 4.0.

[pause-audit.md](pause-audit.md) found that the counted runs of 7 XLTW-Test instances had been paused by the host:
n7037, n8389, n8575, n9160, n9363, n9571 and n10001. [score.md](score.md) scored G0-G5 on all 100 as they stood,
and that scoring stays as it is. This file fixes, before any new run, how those 7 are run again and how they enter a
second scoring.

**What runs.** Job `xltwrerun-v1`: the same harness and solver as every `xltwrun` part (commit `ba1eec8`:
`solver.py`, `xltwrun.py`, `test_xltwrun.py`; `xltwlb.py` and `xltwbase.py` from v0.3.7), the same seed
(20261104), the same limit (T(n)/30), one instance at a time (`--workers 1`), 1 CPU, 5 GB. Each instance is its own
part (`r7037`, `r8389`, `r8575`, `r9160`, `r9363`, `r9571`, `r10001`), so a pause can only touch one result file.
Nothing in the solver or the harness changes.

**What counts as clean.** A run is clean if the harness calls it valid (as before) **and** the job runner's log has
no pause or resume of the job's container between that run's start and end (method of pause-audit.md: the run
step's start from `run.exits` plus each run's wall time, ±10 s). A run that is not clean is re-run in a new job,
unchanged, at most twice more (3 attempts per instance in all). An instance with no clean run after 3 attempts stays
as it is in the merge and is reported as such.

**How it is scored.** Once every instance has a clean run or has used its 3 attempts, the pre-registered
`xltwrun.py --merge` runs once more with each clean re-run in place of the old result for that instance and
everything else exactly as in `xltwmerge-v1`. The second scoring of G0-G5 is published next to the first, and both
are kept. G0-G5 are not reworded. Only the 7 re-runs are new data. The other 93 results are the ones already
published.

**What we expect, so it can be checked:** none of the 7 clean runs needs SIGTERM or SIGKILL, so if all 7 are clean,
G0 and G1 hold in the second scoring unless something else fails; G2, G4 and G5 still do not hold (they miss by far
more than 7 instances can change); G3 still holds.
